# Subscription Schedules

## Modules and interface

`js/subscriptions.js` owns schedule CRUD, renewal decisions, reminders and dedicated management windows. `js/subscription-services.js` owns service identities, aliases, name matching and artwork selection. `js/subscription-assets.js` lists bundled SVG/WebP artwork for both the UI and service worker. Images, library licences and per-asset provenance live in `img/subscriptions/`; subscription names are never sent to a logo service.

Subscriptions sits beside Debts in I Owe's existing view row, keeping the two-row dashboard layout aligned with Owes Me. If debt widgets are hidden, the same area exposes subscription controls alone. Management remains outside Settings. The manager's Add New action shares the search/filter toolbar below its separate title/close row. The notice area attached to Recent Transactions shows the first three subscriptions/dated debts due within seven calendar days, including overdue entries, ordered by due date. Each row displays its logo/icon, full name, relative due date and amount; and X more opens the complete upcoming-payments view. Undated installment schedules are excluded rather than assigned guessed deadlines.

## Portable records

Optional root-level JSON arrays `subscriptions` and `subscriptionOccurrences` map to schema-2 IndexedDB stores. Absence in older backups is valid. The existing backup object, Supabase user_data row and manual Sync workflow are unchanged. Unknown compatible root/record fields survive validation and save; unsupported core subscription enums or malformed records reject the import before replacement.

Each subscription has an existing-style unique `id`, personal `name`, positive LKR `amount`, `method` (bank/cc), optional account/category defaults, `frequency` (daily/weekly/monthly/quarterly/semiannually/annually), local-date `nextDueDate`, `anchorDay` (1–31), `status` (active/paused/cancelled), optional `serviceId` and generic `icon`. The UI labels annually as Annual and semiannually as Bi-Annual, positioned between Quarterly and Annual; it continues to mean every six months. Paused contains paused and legacy cancelled records. Delete removes the schedule and its temporary snooze, retaining financial entries, balances and legacy history. Old cancelled statuses remain compatible without automatically deleting their records.

The editor uses one Last Paid / Next Due Date field. A new or changed past date anchors the recurrence and advances to the first renewal on or after today; a calculated-date preview makes the interpretation visible. Today/future dates are used directly. No previous payment or skipped-occurrence history is invented. Unchanged date/frequency on an existing overdue schedule remains overdue when other fields are edited. This affects explicit schedule entry only; loading an older backup does not advance its saved dates.

New payments are independent expense/CC records: no `subscriptionId`, `subscriptionOccurrenceId`, paid-history row or external-confirmation row is created. The subscription's next due date is the only payment-progress state. `subscriptionOccurrences` is used only for temporary six-hour snoozes on new actions, keyed by subscription ID plus due date. Paying, skipping, changing a date or deleting a schedule clears the relevant snooze. Legacy paid/skipped records, external-confirmation fields and existing financial link metadata remain readable and round-trip backups unchanged, but do not control payment eligibility or date editing.

Deleting an expense alone does not rewind its schedule. Users can edit its renewal date back directly, without a Reopen Renewal confirmation or checking any historical payment. Date/frequency edits refresh the `renewalRevision` reminder token and leave financial records/balances unchanged. A subscription due today is payable even if an older backup contains a handled marker for that date. Repeated submission of the same open payment form still fails once its due date has advanced; stale drafts and atomic storage revision checks remain enforced.

## Recording and recurrence

Creating/editing a schedule never deducts money. Pay opens the same editable payment form from management, upcoming payments and due reminders. Bank/cash recording requires a visible account, sufficient funds and valid category; it creates one expense and deducts the balance. CC recording creates one unpaid purchase, with optional category, and enables the existing CC section if hidden. The user later settles that purchase through normal View & Pay, including partial payments and category defaults. Recording the subscription charge does not settle the CC purchase.

The Entry selector has only Add Expense/Add CC Charge and Already Recorded. Already Recorded hides/disables the financial fields and offers Update Renewal, which advances one recurrence without searching for, linking, creating or editing a transaction. Category defaults retain a valid schedule category, then fall back to Subscriptions & Memberships, then a blank Select Category placeholder; no category is recreated after removal. New schedules use the same default. Remind Me Later is shown only on due alerts; management uses Skip Next Renewal and Pause/Resume/Delete and filters only Active/Paused.

The editor places artwork beside the actual saved name input, without a second canonical service-name label. Selecting a suggestion can fill the input visibly; automatic artwork matching does not change capitalization or personal names. The icon button exposes a native generic-icon selector; explicit custom choices survive later name edits, and Service Logo returns to automatic matching. The Recent Transactions notice uses its card's actual padding at each breakpoint for matching edges and left-aligns its overflow link with the icons.

Financial changes, snooze cleanup and next date commit together through saveData. Failed saves restore the previous state; pending writes, stale drafts, PIN locks and outdated database revisions reject writes. A repeated decision for an already advanced renewal cannot create another charge. Already Recorded only advances the date and clears its snooze. Cross-device divergence continues using explicit whole-copy Sync review, not record merging.

Daily/weekly renewals advance one/seven calendar days. Other periods advance by calendar months and clamp to the last available day while retaining anchorDay, including leap years. Each confirmation handles one occurrence; missed periods remain overdue until handled or the date is edited. No catch-up expenses are generated automatically. Remind Me Later snoozes for six hours in one action and changes only the reminder time; the next eligible launch/focus/timer check then reminds again. Skipping advances once without spending. Pause/cancel stop reminders; resuming retains the saved due date.

## Reminders and matching

Due/overdue reminders are grouped when the app is open and unlocked. They avoid open dialogs and active input. A device preference records shown occurrence tokens for the current local day, so removing or snoozing another item does not repeat already-seen reminders. A new due occurrence or expired snooze becomes eligible. Launch/unlock, focus and a minute timer recalculate eligibility. Closed-app Android/OS notifications require separate implementation.

Name matching is case-insensitive and checks whole phrases inside longer personal names. The longest match wins; equally specific brands require an explicit choice. Picking artwork preserves a personal label already identifying that service. A Custom choice overrides automatic artwork. The catalogue contains 130 services, each with bundled brand artwork; initials and generic icons remain available for custom subscriptions and as defensive image-error fallbacks only. Adobe is one catalogue choice matching Creative Cloud, Photoshop, Illustrator, Lightroom, Premiere Pro, Acrobat and Firefly. Lightroom Mobile has its own Lr artwork and a more specific match. Freepik and Magnific select the same Magnific artwork. Legacy Adobe product IDs and freepik resolve at display time; saved IDs, names and unknown fields are not migrated or discarded. Removed catalogue choices do not remove any saved subscription or financial history.

`sources.json` records the source and actual filename of every active logo. SVGs retain their library licences; 24 missing/new logos are optimized to 96px WebP from reviewed official website or app-listing artwork, with refresh references in `official-sources.json`. Brand marks remain the property of their owners; bundling does not imply affiliation or a blanket reuse licence. `tests/fetch-official-subscription-icons.cjs` downloads only assets and records provenance, including the symbol crop from Google's official Play Pass wordmark. `tests/fetch-subscription-icons.cjs --offline` reconciles provenance with the current catalogue while preserving reviewed files. Neither runs in the client. After changing assets, remove only unreferenced artwork, update the shared filename manifest and regenerate frame suggestions. No subscription names or user records are read by these maintenance tools.

SUBSCRIPTION_LIGHT_LOGOS in subscription-assets.js records contrasting frame choices, computed from actual rendered SVG/WebP pixels by tests/subscription-logo-contrast.cjs. It scores the same dark/light colours used by CSS, including alpha compositing. The utility takes an optional Sharp module path and prints suggested metadata; it does not modify source files. Apply updated metadata when changing logos. Runtime rendering uses these bundled choices in either app theme and makes no image-analysis network calls.

## Compatibility and verification

The adjacent public web checkout can be smoke-tested for importing/saving/exporting these unknown fields; that optional test skips when the sibling checkout is absent. Its existing generic JSON preservation retains the new arrays, but it does not manage renewals. The Android model's source-JSON copy/export design also retains unknown collections; this update does not implement Android subscription UI or execute Android tests. Avoid recording the same renewal manually on another client without linking it when returning to beta.

Run npm test for domain, backup, native IndexedDB transaction and schema-upgrade regressions. KAASI_SUBS_QA=1 with tests/serve-sync-qa.cjs provides disposable schedules and fake cloud data for browser QA; never use it with real financial data. Production Supabase policies and physical-device/PWA update behaviour require the existing release verification process.
